# AGENTS.md — AI readme for the Legacy Crafts repo

Read before changing anything. Records what is *not* inferable from filenames: the
gate order, the traps that already cost a debugging session, and the mandatory
change-log process.

## What this repo is

Premium ecommerce for trophies / furniture / artwork: Next.js 16 storefront
(`apps/storefront`, :3000) + Medusa v2.18 (`apps/medusa`, :9000) + `packages/*`
(`schemas` = shared Zod contracts, `observability`, `config`). Razorpay for payments.
Node 24 (`.nvmrc`), pnpm 10.33.3, pnpm workspaces.

## Commands

Gate order matches CI (`lint` → `typecheck` → unit → build):

```bash
pnpm lint && pnpm typecheck && pnpm test   # before finishing
pnpm build                                  # before merging
```

- **Use the root scripts, not `pnpm -r typecheck`.** Root `typecheck`/`build`
  run `pnpm schemas:build` first; `packages/*` resolve each other through
  `dist/`, so a stale or missing `@legacy-crafts/schemas/dist` breaks typecheck,
  tests and the storefront in confusing ways.
- `pnpm dev` runs both apps in parallel. `next dev` allows only ONE dev server
  per project directory.
- Single test: storefront/schemas are **Vitest**, medusa is **Jest** — different
  filename patterns, so a test file in the wrong place silently never runs.
  - storefront: `pnpm --filter @legacy-crafts/storefront exec vitest run src/lib/foo.test.ts`
  - schemas: `pnpm schemas:test`
  - medusa: `pnpm --filter @legacy-crafts/medusa test` — but its script sets
    `TEST_TYPE=unit` with POSIX syntax, so **on Windows it fails**; use
    `cd apps/medusa; $env:TEST_TYPE="unit"; npx jest --runInBand --forceExit`
    (add `--testPathPattern=<name>` to narrow). `test:integration` has the same
    problem and needs a live Postgres at `DATABASE_URL`; it only runs
    `src/modules` tests.
- e2e: `pnpm --filter @legacy-crafts/storefront test:e2e`. Playwright's `webServer`
  runs `pnpm start` (production) unless `E2E_BASE_URL` is set, so `next build`
  must exist; a dev server on :3000 is reused locally. One spec:
  `... exec playwright test e2e/smoke.spec.ts --project=chromium`.
- `make migrate` / `make seed` / `make reindex` are the data ops
  (`npx medusa db:migrate`, `npx medusa exec ./src/scripts/seed.ts`,
  `./scripts/reindex-search.sh`). Makefile + `scripts/*.sh` need bash + tmux
  (`make up` hosts sessions in tmux); on Windows call the underlying commands
  directly.

## Hard-won gotchas

- **Next.js 16**: `params`/`searchParams` are Promises — always `await`.
  `useSearchParams` needs a `<Suspense>` boundary. Version-accurate docs ship in
  `apps/storefront/node_modules/next/dist/docs/`.
- `apps/storefront/AGENTS.md` is **generated by `next dev`** and re-added if
  deleted; commit it rather than fighting the dirty tree. `CLAUDE.md` there is
  just `@AGENTS.md`.
- **Medusa v2 prices are MAJOR units** (₹, not paise): seeding `899900` means
  ₹8,99,900. Promotions created without a campaign stay `draft` — the seed puts
  them in an active campaign and sets `status: "active"` explicitly.
- **Local Postgres is pinned to `postgres:16-alpine`** in `docker-compose.yml`
  for parity with the host cluster, while CI and `.env.example` say 18. Don't
  silently "fix" the pin; ask which target is intended.
- **`next/image` rejects absolute `localhost` URLs** even with the port
  `remotePatterns` in `next.config.ts`. Every backend-sourced image URL goes
  through `localizeImageUrl()` (`apps/storefront/src/lib/images.ts`).
- **Customer data is client-side only**: wishlist/cart/auth use the Medusa SDK
  with a JWT (`apps/storefront/src/lib/medusa.ts`). RSC fetches of customer data
  return 401 — follow the account-page pattern.
- **Account auth guard**: `AUTH_PATHS` in
  `apps/storefront/src/components/features/account/account-shell.tsx` lists pages
  reachable while logged out. New public account pages must be added there or
  they bounce to `/account/login`.
- **`CardTitle` renders a `div`**, not a heading — e2e must not query it by role.
- **Rate limiting is per-node in memory** (`apps/medusa/src/api/middlewares.ts`):
  100/min store, 20/min auth, 5/min reviews, 30/min wishlist posts, 10/min bulk
  upload, 200/min admin. Screenshot/e2e bursts will trip it — expected.
- **axe + scroll reveals**: measuring mid-fade yields fake color-contrast
  violations. Keep the existing pattern — `emulateMedia({ reducedMotion: "reduce" })`,
  scroll the page, wait, then analyze.
- **Inner-page header is a zero-height overlay**: `#main` is already padded with
  `--site-header-h` in `globals.css`, so pages add no header clearance. A page
  root with its own surface colour adds `.under-site-header`; sticky columns need
  `overflow: clip` (not `hidden`) on ancestors.
- **Gold text on cream/champagne fails WCAG AA** — use `text-gold-dark`
  (`--color-gold-dark`) for text-sized gold; `text-gold` is for dark surfaces and
  decorative icons.

## Recorded architecture decisions

- **No Payload CMS.** Blog/CMS is the Medusa `blog` module (one backend, DB, auth).
- **Razorpay chain** — never bypass verification: checkout passes `order_id` +
  session amount → `apps/storefront/src/app/api/checkout/verify-razorpay/route.ts`
  HMAC-verifies before cart completion → `apps/medusa/src/api/webhooks/razorpay/`
  handles captured/failed with the `webhook-events` idempotency module.
- **Imagery**: brand PNG/JPEGs live in `apps/storefront/public/images/` with
  prompts in `manifest.json`; new imagery must match that style and be registered
  there. No placeholder boxes — ever.
- **Deferred on purpose** (`.cursor/plans/KIMI-EXECUTION-STATUS.md`): Google OAuth,
  delete-account, server-persisted notification prefs, listing rating filter,
  Redis-backed rate limiting. Don't "finish" these unasked.

## Brand contract (do not dilute)

Champagne `#FBFBF7` / cream `#E0D8C3` surfaces, walnut `#331207` text, gold
`#B89E6B` accents. Category accents: burgundy `#8A2D25` trophies, midnight blue
`#191D26` furniture, olive/brass artwork. Playfair Display headlines, Inter body.
Tone: minimal, elegant, editorial — "Crafted with intention. Built to last."
Tokens: `apps/storefront/src/app/globals.css`. Spec: `.cursor/plans/00-master-plan.md`.

## Change log (mandatory, not optional)

Every change is logged in `docs/changes/` — see
[`docs/changes/INDEX.md`](docs/changes/INDEX.md): one line in `L1-milestones.md`,
a paragraph (what/why/key files/how verified) in `L2-work-packages.md`, and an
`L3/NNN-short-title.md` file + index row for anything non-trivial. Write entries
with the change, not after. Never edit history — corrections are new entries.
